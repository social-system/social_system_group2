# MILESTONE04: レシート一覧取得の CRUD 処理を追加

## 目的

登録済みレシートを一覧表示するための DB 操作を追加する。

このマイルストーンでは API ルートは追加しない。CRUD 層に一覧取得処理を追加することだけを目的とする。

## 対象範囲

レシートを一覧取得する CRUD 関数を追加する。

`skip` と `limit` による件数制御を行う。

`date_from` と `date_to` による日付絞り込みを行えるようにする。

一覧では明細全件を返さず、一覧用の要約情報を返せるようにする。

## 想定変更ファイル

`app/crud/` 配下のレシート関連ファイル。

必要に応じて、一覧用スキーマを見据えて `app/schemas/` 配下を確認する。

## 一覧データ仕様

一覧では次の情報を返せるようにする。

```json
{
  "id": 1,
  "purchased_at": 20260428,
  "store_name": "サンプルスーパー",
  "total_amount": 500,
  "items_total": 500,
  "adjustment_amount": 0,
  "item_count": 2,
  "created_at": "2026-04-28T12:00:00"
}
```

現行 DB では購入日は `receipts.purchased_at` にあるため、一覧でもレシート単位の `purchased_at` を使う。

## 絞り込み仕様

`skip` は 0 以上とする。

`limit` は 1 以上とする。

`date_from` と `date_to` は `YYYYMMDD` の整数として扱う。

`date_from` が指定された場合、その日付以降に購入されたレシートを対象にする。

`date_to` が指定された場合、その日付以前に購入されたレシートを対象にする。

日付絞り込みの細かい境界条件は、API 実装時にも再確認する。

## 受け入れ条件

登録済みレシートを一覧用データとして取得できる。

`skip` と `limit` が効く。

`date_from` と `date_to` が指定された場合、対象日付範囲のレシートだけを返せる。

一覧取得時に、明細全件をレスポンス用に返す前提の実装にしない。

既存の登録 API と詳細取得 API の動作を壊さない。

## 実装上の注意

このマイルストーンでは API ルートを追加しない。

このマイルストーンでは削除、テスト基盤は追加しない。

日付の比較は Python の `date` 型で行う。`YYYYMMDD` の整数をそのまま DB の `date` カラムと比較しない。
